# SRAI Instructor Guide

## Teaching model

Each session uses the same five-part pattern:

1. State the decision or technical problem.
2. Explain the minimum theory needed.
3. Execute and interpret the notebook.
4. Change one assumption or parameter.
5. Record implications, limitations, and operational controls.

This keeps the programme practical without separating implementation from
mathematical reasoning or governance.

## Standard 120-minute session

| Segment | Minutes | Instructor responsibility |
| --- | ---: | --- |
| Framing and prerequisites | 15 | Establish the problem and vocabulary |
| Guided concepts | 25 | Explain equations, assumptions, and trade-offs |
| Notebook walkthrough | 35 | Execute cells and interpret outputs |
| Learner modification | 30 | Assign a bounded change or scenario |
| Review and exit check | 15 | Verify understanding and capture questions |

## Assessment

| Component | Weight |
| --- | ---: |
| Executed notebook portfolio | 30% |
| Short interpretation notes | 20% |
| Applied assignments | 20% |
| Capstone implementation | 20% |
| Capstone explanation and defense | 10% |

### Capstone rubric

- Problem and decision relevance: 15%
- Data provenance and quality: 15%
- Methodological correctness: 20%
- Reproducibility and testing: 15%
- Interpretation and uncertainty: 15%
- Responsible-AI and security controls: 10%
- Communication and usability: 10%

## Delivery controls

- Start every cohort from the released environment and immutable catalog.
- Run the full execution audit before the first session.
- Keep learner data separate from demonstration data.
- Do not use sensitive institutional data in public demonstrations.
- Record notebook, package, and dataset versions for assessed work.
- Treat a successful execution as necessary but not sufficient: instructors
  must also review interpretation and assumptions.

## Instructor preparation checklist

- Confirm the selected pathway and calendar.
- Review prerequisite notebooks.
- Execute the assigned notebook set.
- Prepare one local or sector-relevant example.
- Define the required learner modification.
- Prepare expected outputs and common failure explanations.
- Apply the assessment rubric consistently.
